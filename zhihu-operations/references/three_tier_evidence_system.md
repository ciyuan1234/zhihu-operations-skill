# 知乎技术回答三级证据链门禁 (Three-Tier Evidence System)

> 核心法则：知乎读者聚集了大量高水准工程师、算法研究员与高校科研人员。技术内容一旦出现假数据或伪精度指标，会被高权重同行在评论区瞬间撕穿，触发大量专业反对票直接沉底。
> 任何进入正文的参数与结论，必须严格受控于本「三级证据门禁」。

---

## 一、三级证据链体系结构

```
[Level 1: 官方文档事实] -> 厂商官方 Release Notes / 架构白皮书 / 官方定价标准
         ↓
[Level 2: 可复现本地实测] -> 实际磁盘路径 / 本地压测日志 / 真实截屏 / 完整 Traceback
         ↓
[Level 3: 个人定性观察] -> 缺乏严谨打点时，仅使用定性词汇，绝对禁止伪造数字！
```

---

## 二、各层级准入规范与判例

### Tier 1：官方文档与架构事实 (Official Documentation Facts)
- **定义**：可直接追溯至官方官方 GitHub 提交、Release 说明、官方博客或技术白皮书的内容。
- **写作规范**：指明具体的软件版本号与官方机制名称。
  - ✅ **正确**：「在 Docker Desktop v4.34 中，官方正式将 VirtioFS 设为 macOS 默认文件共享实现」
  - ❌ **错误**：「Docker 最近优化了底层性能」

---

### Tier 2：可复现本地基准与实测证据 (Reproducible Benchmarks)
- **定义**：作者在真实开发机上亲自运行、具有本地原始日志或截图存档的数据。
- **严格铁律：禁止伪造伪精度数字！**
  - 在没有真实压测脚本与日志支持的情况下，**严禁凭空编造看似极其专业的虚假参数**（如「耗时 18.2 秒」、「消耗 14,800 token」、「性能提升 3.84 倍」、「准确率 71.3%」）。
  - 所有精确到小数点的数字，在工程空间中必须存在对应的测试输出文件或截图。
- **写作规范**：
  - ✅ **正确**：「在 M3 Pro (18GB) 上运行 5 次平均耗时为 4.2 秒，日志记录在本地 `benchmark_run.log`」
  - ❌ **错误**：「经过我们自研测试，速度提升了整整 4.7 倍」

---

### Tier 3：个人定性观察 (Qualitative Observations)
- **定义**：作者在日常使用中获得的直观感受，但未进行严密仪器测量或打点统计。
- **降级保护准则**：
  - 当缺乏可复现的精确测试环境时，**必须诚实退回定性描述**，绝对不能为了显得专业而编造假数据！
  - 允许使用：「日常调用响应明显顺畅很多」、「在超大文件（>50MB）场景下偶发卡顿」、「内存开销比之前轻量许多」。
  - 真实定性的直觉分享，远比破绽百出的假数字更能赢得专业读者的信任。

---

## 三、跨平台配置安全红线 (Cross-Platform Safety)

在解答涉及 Windows、WSL2、macOS 的跨系统环境配置问题时：
1. **严禁建议跨系统共享可变 SQLite/状态目录**：
   - 例如在 WSL2 中设置 `export CODEX_HOME=/mnt/c/...` 强行复用 Windows 宿主机的配置与会话。这会导致跨系统的文件锁冲突、迁移竞争与数据损坏（参见官方 Issue #23251）。必须建议在各个系统环境中保持独立的身份认证与本地存储。
2. **优先使用项目级隔离配置而非全局覆盖**：
   - 优先推荐在项目根目录下维护 `.gitattributes`（如 `* text=auto eol=lf`），而不是建议读者全局粗暴覆写 `git config --global core.autocrlf false` 导致其它工程换行符紊乱。
